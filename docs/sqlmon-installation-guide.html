SQLMon 安装部署方案

适用项目：/Users/chenxuan/sql/.worktrees/sqlmon-p0

SQLMon 是一个 SQL Server 实时监控平台，当前项目由 FastAPI 后端、Vue/Vite 前端、PostgreSQL 持久化数据库和 SQL Server ODBC 采集器组成。本文档给出 Windows 与 Ubuntu 的安装方案、启动方式、数据库和端口设置、迁移方案，以及默认管理员账号信息。

后端 Python 3.11+ / FastAPI / Uvicorn
前端 Vue 3 / Vite / npm build
数据库 PostgreSQL + Alembic 迁移
采集 pyodbc + ODBC Driver 18
生产环境必须替换默认数据库密码、默认管理员密码，并配置长度不少于 32 字符的 SQLMON_SECRET_KEY。

1. Windows 安装方案

1.1 安装依赖

Windows 环境建议用于开发、测试或小规模内网部署。需要预先安装以下组件：

组件 版本/说明
Python 3.11+
Node.js Node.js LTS，包含 npm
PostgreSQL 用于保存实例配置、快照、审计和用户数据
Microsoft ODBC Driver 18 for SQL Server 用于 pyodbc 连接被监控 SQL Server 实例

ODBC Driver 18 可从 Microsoft 官方页面下载安装：Download ODBC Driver for SQL Server。

1.2 安装步骤

以下示例假设项目放在 C:\sqlmon：

cd C:\sqlmon

py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .\backend

cd .\frontend
npm ci
npm run build

创建后端环境变量文件 C:\sqlmon\backend\.env：

SQLMON_ENV=prod
SQLMON_SECRET_KEY=replace-with-at-least-32-random-characters
SQLMON_DATABASE_URL=postgresql+asyncpg://sqlmon:数据库密码@127.0.0.1:5432/sqlmon
SQLMON_API_HOST=127.0.0.1
SQLMON_API_PORT=8000
SQLMON_LOG_LEVEL=INFO
SQLMON_DEFAULT_RETENTION_DAYS=7
SQLMON_COLLECT_CONNECT_TIMEOUT_SECONDS=5
SQLMON_COLLECT_QUERY_TIMEOUT_SECONDS=3
SQLMON_MIN_KILLABLE_SESSION_ID=50

1.3 启动方式

首次启动前执行数据库迁移：

cd C:\sqlmon\backend
..\.venv\Scripts\Activate.ps1
alembic upgrade head

启动 API 服务：

cd C:\sqlmon\backend
..\.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 127.0.0.1 --port 8000

另开一个 PowerShell 启动 Collector：

cd C:\sqlmon\backend
..\.venv\Scripts\Activate.ps1
python -m app.collector.main

开发态前端启动方式：

cd C:\sqlmon\frontend
npm run dev -- --host 0.0.0.0 --port 5173

生产态 Windows 建议使用 Nginx for Windows 或 IIS：静态目录指向 frontend/dist，并将 /api 反向代理到 http://127.0.0.1:8000。API 与 Collector 可用 NSSM 注册为 Windows Service。

2. Ubuntu 安装方案

2.1 安装依赖

Ubuntu 环境是推荐生产部署方式。需要安装：

  • Python 3.11+ 和 venv。
  • Node.js LTS 和 npm。
  • PostgreSQL。
  • Nginx。
  • Microsoft ODBC Driver 18 for SQL Server。

ODBC Driver 18 建议按 Microsoft 官方文档安装：Installing the Microsoft ODBC Driver for SQL Server on Linux。

2.2 安装步骤

以下示例使用 /opt/sqlmon 作为生产部署目录：

sudo useradd --system --create-home --home-dir /opt/sqlmon --shell /usr/sbin/nologin sqlmon
sudo mkdir -p /opt/sqlmon/{backend,frontend,config,scripts,logs}
sudo chown -R sqlmon:sqlmon /opt/sqlmon

复制项目文件后安装后端和前端依赖：

cd /opt/sqlmon
sudo -u sqlmon python3.11 -m venv venv
sudo -u sqlmon /opt/sqlmon/venv/bin/pip install --upgrade pip
sudo -u sqlmon /opt/sqlmon/venv/bin/pip install -e /opt/sqlmon/backend

cd /opt/sqlmon/frontend
sudo -u sqlmon npm ci
sudo -u sqlmon npm run build

准备环境变量文件：

sudo cp deploy/env/app.env.example /opt/sqlmon/config/app.env
sudo vim /opt/sqlmon/config/app.env

/opt/sqlmon/config/app.env 至少应包含：

SQLMON_ENV=prod
SQLMON_SECRET_KEY=replace-with-at-least-32-random-characters
SQLMON_DATABASE_URL=postgresql+asyncpg://sqlmon:change-me@127.0.0.1:5432/sqlmon
SQLMON_ENCRYPTION_KEY=replace-with-encryption-key
SQLMON_API_HOST=127.0.0.1
SQLMON_API_PORT=8000
SQLMON_LOG_LEVEL=INFO
SQLMON_DEFAULT_RETENTION_DAYS=7
SQLMON_COLLECT_CONNECT_TIMEOUT_SECONDS=5
SQLMON_COLLECT_QUERY_TIMEOUT_SECONDS=3
SQLMON_MIN_KILLABLE_SESSION_ID=50

2.3 启动方式

复制项目自带脚本并执行迁移：

sudo cp deploy/scripts/*.sh /opt/sqlmon/scripts/
sudo chmod +x /opt/sqlmon/scripts/*.sh

sudo -u sqlmon APP_HOME=/opt/sqlmon /opt/sqlmon/scripts/migrate.sh

注册并启动 systemd 服务：

sudo cp deploy/systemd/sqlmon-api.service /etc/systemd/system/
sudo cp deploy/systemd/sqlmon-collector.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sqlmon-api sqlmon-collector

配置 Nginx：

sudo cp deploy/nginx/sqlmon.conf /etc/nginx/sites-available/sqlmon.conf
sudo ln -s /etc/nginx/sites-available/sqlmon.conf /etc/nginx/sites-enabled/sqlmon.conf
sudo nginx -t
sudo systemctl reload nginx

启动后访问：

地址 说明
http://服务器IP/ 前端页面
http://服务器IP/api/health API 健康检查，期望返回 {"status":"ok"}

3. 数据库和端口设置

3.1 PostgreSQL 设置

SQLMon 使用 PostgreSQL 保存平台数据。初始化数据库和用户：

CREATE USER sqlmon WITH PASSWORD '强密码';
CREATE DATABASE sqlmon OWNER sqlmon;
GRANT ALL PRIVILEGES ON DATABASE sqlmon TO sqlmon;

后端通过 SQLMON_DATABASE_URL 指定连接串：

SQLMON_DATABASE_URL=postgresql+asyncpg://sqlmon:强密码@127.0.0.1:5432/sqlmon

3.2 端口设置

端口 组件 配置方式 说明
5432 PostgreSQL PostgreSQL 配置 平台主数据库端口
8000 FastAPI API SQLMON_API_HOST / SQLMON_API_PORT 默认监听 127.0.0.1:8000
5173 Vite 开发服务 npm run dev -- --port 5173 开发态前端端口
80 Nginx deploy/nginx/sqlmon.conf 生产态 Web 入口，反代 /api 到 API
1433 SQL Server 实例配置页面或实例 API 被监控 SQL Server 默认端口

前端生产态默认请求同源 /api；开发态 Vite 配置会把 /api 代理到 http://localhost:8000。

3.3 SQL Server 接入权限

实例接入在登录后通过“实例设置”维护。创建实例时可填写 SQL Server 主机、端口、数据库、SQL 认证用户名和密码，也可直接提供采集 DSN。

系统默认使用 ODBC Driver 18 for SQL Server，生成的 SQL 认证连接串会包含：

Driver={ODBC Driver 18 for SQL Server};
Server={host,1433};
Database={master};
UID={username};
PWD={password};
Encrypt=yes;
TrustServerCertificate=yes;

SQL Server 采集账号权限：

-- SQL Server 2019 及以前
GRANT VIEW SERVER STATE TO [sqlmon_collect];

-- SQL Server 2022 及以后
GRANT VIEW SERVER PERFORMANCE STATE TO [sqlmon_collect];

如需 Kill Session 功能，建议单独配置 Kill 账号：

GRANT ALTER ANY CONNECTION TO [sqlmon_kill];
如果企业安全要求更高，可以不配置 Kill 账号，平台仅展示 Kill 建议，由 DBA 登录 SSMS 手动执行。

4. 迁移和默认账号

4.1 数据迁移方案

SQLMon 使用 Alembic 管理数据库结构。初始化和升级都执行：

cd backend
alembic upgrade head

Ubuntu 生产环境可使用项目脚本：

APP_HOME=/opt/sqlmon /opt/sqlmon/scripts/migrate.sh

生产升级建议流程：

  1. 停止 API 和 Collector，避免升级期间继续写入快照。
  2. 备份 PostgreSQL 数据库。
  3. 发布新代码和前端构建产物。
  4. 执行 alembic upgrade head。
  5. 启动 API、Collector 和 Nginx。
  6. 访问 /api/health 和前端页面验证。

PostgreSQL 备份示例：

pg_dump -Fc -d sqlmon -f sqlmon_$(date +%F).dump

当前迁移链包含：

迁移 说明
0001_initial_schema 初始化核心表结构
0002_seed_default_admin_user 创建默认管理员用户
0003_snapshot_resource_metrics 增加快照资源指标
0004_missing_index_audits 增加缺失索引审计
0005_split_network_metrics 拆分网络资源指标
0006_index_snapshots 增加索引采集快照
0007_index_page_indexes 增加索引快照分页索引
0008_async_index_ddl 增加异步索引 DDL 设置

4.2 默认账号和密码

默认管理员由迁移 0002_seed_default_admin_user 初始化：

项目 值
用户名 admin
密码 Admin@2026
显示名 系统管理员
角色 admin
状态 active

迁移脚本对 username=admin 使用冲突跳过逻辑，因此已有管理员不会被覆盖。首次登录后建议立即进入用户管理页面修改密码。
